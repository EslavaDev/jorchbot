# Phase 1 — WhatsApp Channel + Single Session

> **Status**: Near Complete (implementation ~95% done, manual test items remain)
> **Dependency**: Phase 0 (completed)
> **Deliverable**: Talk to ONE Claude Code instance from WhatsApp via Kapso.ai
> **When finished**: You send a message via WP → ClaudeRunner processes it → you receive a response

---

## 1. WHY — Why this phase

JorchBot without this phase is just an empty fork. Phase 0 established the foundation (config, DB, errors, CLI placeholders), but there is no real communication with Claude Code nor with any messaging channel.

This phase is the first one that produces **real value**: the user can send a WhatsApp message and receive a response generated by Claude Code headless. It is the heart of the product.

**What is built**:

1. **Kapso channel plugin** — receives/sends WhatsApp messages via official Meta API
2. **ClaudeRunner** — executes Claude Code as a subprocess and parses its output
3. **Basic approval flow** — Yes/No buttons in WhatsApp
4. **Basic command router** — /help, /status, free text → Claude
5. **Context window % tracking** — how much context remains per session
6. **Gateway integration** — connects JorchBot with the OpenClaw gateway

**What is NOT built** (later phases):

- Multi-session and Focus Model (Phase 2)
- Direct shell with `$` (Phase 2)
- Jorchfile engine (Phase 3)
- Automatic tunnels (Phase 4)
- "Yes + feedback", plan/auto/silent modes, Kapso lists (Phase 5)

---

## 2. WHAT — What is delivered

### 2.1 Kapso Channel Plugin (`extensions/kapso/`)

A channel plugin for OpenClaw that connects WhatsApp via the official Meta API (Kapso.ai). It follows the exact pattern of `extensions/whatsapp/` (Baileys), but uses the Kapso REST API instead of WebSocket+Baileys.

**Inherited for free from the Plugin SDK**:

- DM pairing (6-digit code)
- Message chunking (4096 chars for WP)
- Access control (4 policies: pairing, allowlist, open, disabled)
- Message normalization and routing pipeline
- Session key generation

**Implements**:

- Webhook receiver (incoming messages via HTTP POST)
- Message sender (text, interactive buttons)
- Config adapter (account listing/resolution)
- Security adapter (DM policy)
- Pairing adapter (phone number normalization)
- Gateway adapter (webhook listener start/stop)
- Outbound adapter (text, media, buttons sending)
- Status adapter (connection health check)

### 2.2 ClaudeRunner (`src/sessions/jorchbot/claude-runner.ts`)

A 100% JorchBot-specific component (Layer 2). Executes Claude Code as a headless subprocess and parses its NDJSON output in streaming.

**Responsibilities**:

- Spawn: `claude -p <prompt> --output-format stream-json --dangerously-skip-permissions`
- Resume: `claude -p <prompt> --resume <session_id> --output-format stream-json --dangerously-skip-permissions`
- Parse streaming NDJSON (line by line)
- Inject system prompt via `--append-system-prompt` (PLAN_MODE_PROMPT for Phase 1)
- Emit events for text responses, tool use (informational), and results
- Calculate context window % from response metadata
- Handle errors, timeouts, and unexpected process closure
- Stop the session cleanly (SIGTERM → SIGKILL fallback)

> **NOTE (rev. 3 — 2026-02-19)**: Claude Code headless (`-p`) with stdin piped hangs
> before emitting events. The `--dangerously-skip-permissions` flag is required for headless
> operation, combined with `stdin: "ignore"`. Tool-level approval via stdin does NOT work.
> Phase 1 uses a conversational system prompt approach instead. Phase 2 replaces this with
> real tool-level approval via Claude Code `PreToolUse` hooks.

### 2.3 Approval flow (Phase 1 — conversational via system prompt)

> **NOTE (rev. 3 — 2026-02-19)**: Tool-level approval via stdin does NOT work in headless mode.
> Claude Code hangs when stdin is piped. Phase 1 uses a conversational approach as an interim
> solution. Phase 2 replaces this with real tool-level approval via `PreToolUse` hooks.

In Phase 1, approval is handled conversationally via a system prompt (`PLAN_MODE_PROMPT`):

1. ClaudeRunner injects `PLAN_MODE_PROMPT` via `--append-system-prompt`
2. The prompt instructs Claude to: investigate first, present a plan, wait for user confirmation
3. User confirms with "dale"/"go"/"si" or rejects with "no"/"para"/"cancel"
4. Claude executes (or doesn't) based on user's conversational response
5. There is **no per-tool approval** — the entire plan is approved/rejected as a whole

The `ApprovalManager` still exists for recording approval metadata in the DB, but it operates
at the conversational level (plan approval), not at the individual tool level.

> **Phase 2**: Each individual tool use (Edit, Bash, Write) is approved via `PreToolUse` hooks
> that send WhatsApp buttons [Yes] [No]. See `docs/phase-2-multi-session.md` section 2.7.

### 2.4 Basic Command Router

Parses incoming messages and decides what to do:

- `/help` → shows list of available commands
- `/status` → gateway status, active session, context %
- Text without `/` → sends as prompt to ClaudeRunner
- Error if there is no active session and free text is sent

### 2.5 Context Window % Tracking

Each Claude Code response includes metadata with token usage. JorchBot:

- Parses `input_tokens` and `output_tokens` from the response
- Calculates % based on the model limit (200K for Claude)
- Includes in each response: `Context: X% (YK/ZK tokens)`
- Saves in DB (`sessions` table, `contextPercent` field)

### 2.6 Gateway Integration

Connects `jorchbot-start.ts` with the real OpenClaw gateway:

- Starts the OpenClaw gateway server
- Loads the Kapso channel plugin
- Connects ClaudeRunner to the message pipeline
- Handles graceful shutdown (stops ClaudeRunner + closes DB)

### 2.7 Onboarding (`jorchbot setup`)

Interactive command to configure JorchBot for the first time:

1. Ask for Kapso API key
2. Ask for Kapso phone number ID
3. Configure webhook verify token
4. Show webhook URL to configure in Kapso dashboard
5. Send test message
6. Save to `~/.jorchbot/config.json`

#### 3.2.4 Kapso API Client

```typescript
// extensions/kapso/src/client.ts
import { KapsoClientError } from "./types.js";

interface KapsoClientOptions {
  apiKey: string;
  phoneNumberId: string;
  baseUrl?: string;
}

interface SendTextOptions {
  to: string;
  body: string;
}

interface SendButtonsOptions {
  to: string;
  body: string;
  buttons: Array<{ id: string; title: string }>;
}

interface KapsoSendResult {
  messageId: string;
}

/**
 * Thin wrapper around the Kapso.ai WhatsApp Cloud API.
 *
 * Uses fetch() directly instead of @kapso/whatsapp-cloud-api SDK
 * to minimize dependencies and maintain full control over error handling.
 * Kapso's REST API is simple enough that a dedicated SDK isn't warranted.
 *
 * @throws {KapsoClientError} On any API call failure
 */
export class KapsoClient {
  private readonly apiKey: string;
  private readonly phoneNumberId: string;
  private readonly baseUrl: string;

  constructor(options: KapsoClientOptions) {
    this.apiKey = options.apiKey;
    this.phoneNumberId = options.phoneNumberId;
    this.baseUrl = options.baseUrl ?? "https://api.kapso.ai/meta/whatsapp";
  }

  /**
   * Send a plain text message.
   * @throws {KapsoClientError} If the API call fails
   */
  async sendText(options: SendTextOptions): Promise<KapsoSendResult> {
    return this.post("/messages", {
      messaging_product: "whatsapp",
      recipient_type: "individual",
      to: options.to,
      type: "text",
      text: { body: options.body },
    });
  }

  /**
   * Send an interactive message with buttons (max 3).
   * @throws {KapsoClientError} If the API call fails
   */
  async sendButtons(options: SendButtonsOptions): Promise<KapsoSendResult> {
    if (options.buttons.length > 3) {
      throw new KapsoClientError(`WhatsApp buttons limited to 3, got ${options.buttons.length}`);
    }
    return this.post("/messages", {
      messaging_product: "whatsapp",
      recipient_type: "individual",
      to: options.to,
      type: "interactive",
      interactive: {
        type: "button",
        body: { text: options.body },
        action: {
          buttons: options.buttons.map((btn) => ({
            type: "reply",
            reply: { id: btn.id, title: btn.title },
          })),
        },
      },
    });
  }

  /**
   * Send a document (for long outputs).
   * @throws {KapsoClientError} If the API call fails
   */
  async sendDocument(options: {
    to: string;
    documentUrl: string;
    filename: string;
    caption?: string;
  }): Promise<KapsoSendResult> {
    return this.post("/messages", {
      messaging_product: "whatsapp",
      recipient_type: "individual",
      to: options.to,
      type: "document",
      document: {
        link: options.documentUrl,
        filename: options.filename,
        caption: options.caption,
      },
    });
  }

  private async post(path: string, body: unknown): Promise<KapsoSendResult> {
    const url = `${this.baseUrl}/${this.phoneNumberId}${path}`;

    let response: Response;
    try {
      response = await fetch(url, {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          Authorization: `Bearer ${this.apiKey}`,
        },
        body: JSON.stringify(body),
      });
    } catch (err: unknown) {
      throw new KapsoClientError(
        `Network error calling Kapso API: ${err instanceof Error ? err.message : String(err)}`,
        { cause: err },
      );
    }

    if (!response.ok) {
      const errorBody = await response.text().catch(() => "unknown");
      throw new KapsoClientError(`Kapso API error ${response.status}: ${errorBody}`);
    }

    const data = (await response.json()) as { messages?: Array<{ id: string }> };
    const messageId = data.messages?.[0]?.id ?? "unknown";
    return { messageId };
  }
}
```

#### 3.2.6 Webhook handler

```typescript
// extensions/kapso/src/webhook.ts
import type { Request, Response } from "express";
import { KapsoWebhookVerificationError } from "./types.js";
import type { KapsoWebhookPayload, KapsoIncomingMessage } from "./types.js";

interface WebhookHandlerDeps {
  verifyToken: string;
  onMessage: (message: KapsoIncomingMessage, senderPhone: string) => Promise<void>;
  onButtonReply: (buttonId: string, senderPhone: string) => Promise<void>;
}

/**
 * Create Express route handlers for Kapso webhooks.
 *
 * Two routes:
 * - GET  /webhooks/kapso — verification challenge (Kapso setup)
 * - POST /webhooks/kapso — incoming messages
 *
 * @throws {KapsoWebhookVerificationError} If verification token doesn't match
 */
export function createWebhookHandlers(deps: WebhookHandlerDeps) {
  return {
    /**
     * Handle Kapso webhook verification (GET).
     * Kapso sends hub.mode, hub.verify_token, hub.challenge.
     */
    verify(req: Request, res: Response): void {
      const mode = req.query["hub.mode"] as string | undefined;
      const token = req.query["hub.verify_token"] as string | undefined;
      const challenge = req.query["hub.challenge"] as string | undefined;

      if (mode !== "subscribe" || token !== deps.verifyToken) {
        throw new KapsoWebhookVerificationError(
          `Webhook verification failed: mode=${mode}, token mismatch`,
        );
      }

      res.status(200).send(challenge);
    },

    /**
     * Handle incoming Kapso webhook (POST).
     * Always returns 200 immediately (Kapso retries on non-200).
     */
    async receive(req: Request, res: Response): Promise<void> {
      // Always respond 200 first — Kapso retries on timeout
      res.sendStatus(200);

      const payload = req.body as KapsoWebhookPayload;

      if (payload.object !== "whatsapp_business_account") {
        return;
      }

      for (const entry of payload.entry) {
        for (const change of entry.changes) {
          if (change.field !== "messages") continue;

          const messages = change.value.messages ?? [];
          for (const msg of messages) {
            if (msg.type === "interactive" && msg.interactive?.button_reply) {
              await deps.onButtonReply(msg.interactive.button_reply.id, msg.from);
            } else if (msg.type === "text" && msg.text?.body) {
              await deps.onMessage(msg, msg.from);
            }
            // Other message types (image, document, etc.) ignored in Phase 1
          }
        }
      }
    },
  };
}
```

#### 3.2.7 Channel plugin (`kapsoPlugin`)

```typescript
// extensions/kapso/src/channel.ts
import type { ChannelPlugin } from "openclaw/plugin-sdk";
import { DEFAULT_ACCOUNT_ID, formatPairingApproveHint, normalizeE164 } from "openclaw/plugin-sdk";
import { getKapsoRuntime } from "./runtime.js";
import { KapsoClient } from "./client.js";
import type { ResolvedKapsoAccount } from "./types.js";

// Client cache per account
const clients = new Map<string, KapsoClient>();

function getClient(account: ResolvedKapsoAccount): KapsoClient {
  const key = account.accountId;
  let client = clients.get(key);
  if (!client) {
    client = new KapsoClient({
      apiKey: account.apiKey,
      phoneNumberId: account.phoneNumberId,
    });
    clients.set(key, client);
  }
  return client;
}

export const kapsoPlugin: ChannelPlugin<ResolvedKapsoAccount> = {
  id: "kapso",
  meta: {
    id: "kapso",
    label: "Kapso (WhatsApp)",
    selectionLabel: "Kapso WhatsApp",
    docsPath: "channels/kapso",
    blurb: "WhatsApp via Kapso.ai official Meta API",
    order: 1,
    quickstartAllowFrom: true,
    forceAccountBinding: true,
  },

  capabilities: {
    chatTypes: ["direct"],
    // No group support in Phase 1 (Kapso doesn't support groups yet)
    polls: false,
    reactions: false,
    media: false, // Phase 1: text + buttons only
  },

  pairing: {
    idLabel: "whatsappSenderId",
    normalizeAllowEntry: (raw) => normalizeE164(String(raw)),
  },

  config: {
    listAccountIds: (cfg) => {
      const accounts = cfg.channels?.kapso?.accounts;
      if (!accounts) return [DEFAULT_ACCOUNT_ID];
      return Object.keys(accounts);
    },

    resolveAccount: (cfg, accountId) => {
      const id = accountId || DEFAULT_ACCOUNT_ID;
      const kapsoConfig = cfg.channels?.kapso;
      const accountConfig = kapsoConfig?.accounts?.[id] ?? kapsoConfig;

      return {
        accountId: id,
        name: ((accountConfig as Record<string, unknown>)?.name as string) ?? id,
        enabled: (accountConfig as Record<string, unknown>)?.enabled !== false,
        apiKey: ((accountConfig as Record<string, unknown>)?.apiKey as string) ?? "",
        phoneNumberId: ((accountConfig as Record<string, unknown>)?.phoneNumberId as string) ?? "",
        webhookVerifyToken:
          ((accountConfig as Record<string, unknown>)?.webhookVerifyToken as string) ?? "",
        dmPolicy:
          ((accountConfig as Record<string, unknown>)
            ?.dmPolicy as ResolvedKapsoAccount["dmPolicy"]) ?? "pairing",
        allowFrom: ((accountConfig as Record<string, unknown>)?.allowFrom as string[]) ?? [],
      };
    },

    defaultAccountId: () => DEFAULT_ACCOUNT_ID,

    isEnabled: (account) => account.enabled && Boolean(account.apiKey),

    isConfigured: async (account) => Boolean(account.apiKey) && Boolean(account.phoneNumberId),

    describeAccount: (account) => ({
      accountId: account.accountId,
      name: account.name,
      enabled: account.enabled,
      configured: Boolean(account.apiKey),
      linked: Boolean(account.apiKey),
      dmPolicy: account.dmPolicy,
      allowFrom: account.allowFrom,
    }),
  },

  security: {
    resolveDmPolicy: ({ account }) => ({
      policy: account.dmPolicy ?? "pairing",
      allowFrom: account.allowFrom ?? [],
      policyPath: "channels.kapso.dmPolicy",
      allowFromPath: "channels.kapso.",
      approveHint: formatPairingApproveHint("kapso"),
      normalizeEntry: (raw) => normalizeE164(String(raw)),
    }),
  },

  outbound: {
    deliveryMode: "direct",
    textChunkLimit: 4096,
    chunker: (text, limit) => getKapsoRuntime().channel.text.chunkText(text, limit),
    chunkerMode: "text",

    resolveTarget: ({ to }) => ({
      ok: true,
      target: { id: to, displayName: to },
    }),

    sendText: async ({ to, text, accountId, deps }) => {
      // In Phase 1, resolve the account from config to get the client
      // The deps pattern allows test injection
      const sendFn = deps?.sendKapso;
      if (sendFn) {
        return sendFn(to, text);
      }

      // Actual sending uses the KapsoClient
      // This requires the account to be resolved by the gateway
      // The runtime provides the config to resolve the account
      const cfg = getKapsoRuntime().config.loadConfig();
      const account = kapsoPlugin.config.resolveAccount(cfg, accountId);
      const client = getClient(account);
      const result = await client.sendText({ to, body: text });
      return { channel: "kapso", messageId: result.messageId, toJid: to };
    },

    sendMedia: async ({ to, text, mediaUrl, accountId }) => {
      // Phase 1: documents only (for long output files)
      if (!mediaUrl) {
        // Fallback to text if no media URL
        const cfg = getKapsoRuntime().config.loadConfig();
        const account = kapsoPlugin.config.resolveAccount(cfg, accountId);
        const client = getClient(account);
        const result = await client.sendText({ to, body: text ?? "" });
        return { channel: "kapso", messageId: result.messageId, toJid: to };
      }

      const cfg = getKapsoRuntime().config.loadConfig();
      const account = kapsoPlugin.config.resolveAccount(cfg, accountId);
      const client = getClient(account);
      const result = await client.sendDocument({
        to,
        documentUrl: mediaUrl,
        filename: "output.txt",
        caption: text,
      });
      return { channel: "kapso", messageId: result.messageId, toJid: to };
    },
  },

  gateway: {
    startAccount: async (ctx) => {
      ctx.log?.info(`[kapso/${ctx.accountId}] starting Kapso webhook listener`);
      ctx.setStatus({ accountId: ctx.accountId, running: true, connected: true });
      // The webhook listener is registered as an HTTP route on the gateway
      // via api.registerHttpRoute() during plugin registration.
      // startAccount just marks the account as running.
    },

    stopAccount: async (ctx) => {
      ctx.log?.info(`[kapso/${ctx.accountId}] stopping Kapso webhook listener`);
      clients.delete(ctx.accountId);
      ctx.setStatus({ accountId: ctx.accountId, running: false, connected: false });
    },
  },

  status: {
    defaultRuntime: {
      accountId: DEFAULT_ACCOUNT_ID,
      running: false,
      connected: false,
      reconnectAttempts: 0,
      lastConnectedAt: null,
      lastDisconnect: null,
      lastMessageAt: null,
      lastEventAt: null,
      lastError: null,
    },
    buildAccountSnapshot: async ({ account, runtime }) => ({
      accountId: account.accountId,
      name: account.name,
      enabled: account.enabled,
      configured: Boolean(account.apiKey),
      linked: Boolean(account.apiKey),
      running: runtime?.running ?? false,
      connected: runtime?.connected ?? false,
      reconnectAttempts: runtime?.reconnectAttempts ?? 0,
      lastConnectedAt: runtime?.lastConnectedAt ?? null,
      lastDisconnect: runtime?.lastDisconnect ?? null,
      lastMessageAt: runtime?.lastMessageAt ?? null,
      lastEventAt: runtime?.lastEventAt ?? null,
      lastError: runtime?.lastError ?? null,
      dmPolicy: account.dmPolicy,
      allowFrom: account.allowFrom,
    }),
  },
};
```

### 3.3 ClaudeRunner — Detail

#### 3.3.1 Claude Code headless protocol

Claude Code in headless mode (`-p` flag) with `--output-format stream-json` emits NDJSON (one JSON line per event). The relevant events are:

```jsonc
// Session start
{"type":"system","subtype":"init","session_id":"sess_abc123","tools":["Read","Edit","Bash",...]}

// Assistant text response
{"type":"assistant","message":{"role":"assistant","content":[{"type":"text","text":"Analyzing..."}]}}

// Claude wants to use a tool
{"type":"assistant","message":{"role":"assistant","content":[{"type":"tool_use","id":"toolu_xyz","name":"Bash","input":{"command":"npm test"}}]}}

// Tool result (after approval)
{"type":"tool","content":[{"type":"tool_result","tool_use_id":"toolu_xyz","content":"24 tests passed"}]}
```

#### 3.3.2 Claude Code headless limitations and workarounds

> **CRITICAL (rev. 3 — 2026-02-19)**: Claude Code headless (`-p`) with piped stdin **hangs**
> before emitting any NDJSON events. This was discovered during Phase 1 implementation.

**What doesn't work**:

- Piping stdin (`stdio: ["pipe", "pipe", "pipe"]`) causes Claude Code to hang indefinitely
- Writing `"yes\n"` / `"no\n"` to stdin for tool approval never works in headless mode
- `--allowedTools` without `--dangerously-skip-permissions` also causes hangs

**What works (Phase 1 solution)**:

- `--dangerously-skip-permissions` + `stdin: "ignore"` — Claude Code runs without asking
  for per-tool permission. All tools are auto-approved at the process level.
- `--append-system-prompt` injects `PLAN_MODE_PROMPT` — Claude is instructed to present
  a plan and wait for conversational confirmation before executing.
- Approval happens at the **conversation level** (user says "dale"/"go"/"si"), not at the
  individual tool level.

**Phase 2 solution (hooks)**:

Phase 2 replaces conversational approval with real tool-level approval via Claude Code
`PreToolUse` hooks. The hook script calls the JorchBot gateway HTTP API, which sends
WhatsApp buttons to the user. See `specifications/phase-2-multi-session/SPEC.md` section 2.6.

> **NOTE**: The `respondToApproval()` method still exists in the ClaudeRunner code but is
> effectively unused when `skipPermissions: true` (the default in Phase 1). It is retained
> for potential future use or removed in Phase 2.

#### 3.3.3 ClaudeRunner implementation

```typescript
// src/sessions/jorchbot/claude-runner.ts
import { spawn, type ChildProcess } from "node:child_process";
import { createInterface, type Interface as ReadlineInterface } from "node:readline";
import { EventEmitter } from "node:events";
import {
  ClaudeRunnerSpawnError,
  ClaudeRunnerParseError,
  ClaudeRunnerTimeoutError,
  ClaudeRunnerProcessError,
} from "../../errors/index.js";

// --- Types ---

/** Parsed NDJSON event from Claude Code stream */
interface ClaudeStreamEvent {
  type: string;
  subtype?: string;
  session_id?: string;
  message?: {
    role: string;
    content: Array<{
      type: string;
      text?: string;
      id?: string;
      name?: string;
      input?: Record<string, unknown>;
    }>;
  };
  content?: Array<{
    type: string;
    tool_use_id?: string;
    content?: string;
  }>;
  usage?: { input_tokens: number; output_tokens: number };
  cost_usd?: number;
  duration_ms?: number;
}

/** Tool use request detected in the stream */
interface ToolUseRequest {
  toolUseId: string;
  toolName: string;
  toolInput: Record<string, unknown>;
}

/** Final result from a ClaudeRunner invocation */
interface ClaudeRunnerResult {
  sessionId: string;
  textContent: string;
  inputTokens: number;
  outputTokens: number;
  costUsd: number;
  durationMs: number;
}

/** Events emitted by ClaudeRunner */
interface ClaudeRunnerEvents {
  text: [text: string];
  toolUse: [request: ToolUseRequest];
  result: [result: ClaudeRunnerResult];
  error: [error: Error];
}

type ClaudeRunnerStatus = "idle" | "running" | "waiting_approval" | "stopped" | "error";

// --- Constants ---

const CLAUDE_BINARY = "claude";
const DEFAULT_TIMEOUT_MS = 300_000; // 5 minutes
const KILL_TIMEOUT_MS = 5_000; // 5 seconds before SIGKILL
const MODEL_CONTEXT_LIMIT = 200_000; // Claude model context window

// --- Implementation ---

/**
 * Runs Claude Code as a headless subprocess.
 *
 * Spawns `claude -p <prompt> --output-format stream-json`, parses the
 * NDJSON stream, and emits events for text responses, tool approval
 * requests, and final results.
 *
 * This is 100% JorchBot-specific (Layer 2). OpenClaw does NOT execute
 * Claude Code as a subprocess.
 *
 * @throws {ClaudeRunnerSpawnError} If the claude binary cannot be found or spawned
 * @throws {ClaudeRunnerParseError} If NDJSON parsing fails on a critical event
 * @throws {ClaudeRunnerTimeoutError} If the process exceeds the timeout
 * @throws {ClaudeRunnerProcessError} If the process exits with a non-zero code
 */
export class ClaudeRunner extends EventEmitter<ClaudeRunnerEvents> {
  private process: ChildProcess | null = null;
  private readline: ReadlineInterface | null = null;
  private sessionId: string | null = null;
  private status: ClaudeRunnerStatus = "idle";
  private accumulatedText = "";
  private lastInputTokens = 0;
  private lastOutputTokens = 0;
  private timeoutHandle: ReturnType<typeof setTimeout> | null = null;

  /** Current Claude Code session ID (null if never started) */
  getSessionId(): string | null {
    return this.sessionId;
  }

  /** Current runner status */
  getStatus(): ClaudeRunnerStatus {
    return this.status;
  }

  /**
   * Calculate context window usage as a percentage.
   * Based on total tokens used vs model limit.
   */
  getContextPercent(): number {
    const total = this.lastInputTokens + this.lastOutputTokens;
    if (total === 0) return 0;
    return Math.min(100, Math.round((total / MODEL_CONTEXT_LIMIT) * 100));
  }

  /**
   * Start a new Claude Code session.
   *
   * @param prompt The user's message/instruction
   * @param cwd Working directory for Claude Code
   * @param options Additional options
   * @throws {ClaudeRunnerSpawnError} If spawn fails
   */
  async start(options: {
    prompt: string;
    cwd: string;
    systemPrompt?: string;
    skipPermissions?: boolean; // Default: true (required for headless operation)
    timeoutMs?: number;
  }): Promise<ClaudeRunnerResult> {
    const args = ["-p", options.prompt, "--output-format", "stream-json"];

    // --dangerously-skip-permissions is required for headless mode.
    // Without it, Claude Code hangs waiting for stdin approval.
    const skipPerms = options.skipPermissions !== false;
    if (skipPerms) {
      args.push("--dangerously-skip-permissions");
    }

    if (options.systemPrompt) {
      args.push("--append-system-prompt", options.systemPrompt);
    }

    return this.run(args, options.cwd, options.timeoutMs, skipPerms);
  }

  /**
   * Resume an existing Claude Code session.
   *
   * @param prompt The follow-up message
   * @param cwd Working directory (must match original session)
   * @throws {ClaudeRunnerSpawnError} If spawn fails
   * @throws {ClaudeRunnerProcessError} If no session to resume
   */
  async resume(options: {
    prompt: string;
    cwd: string;
    timeoutMs?: number;
  }): Promise<ClaudeRunnerResult> {
    if (!this.sessionId) {
      throw new ClaudeRunnerProcessError("No session to resume. Call start() first.");
    }

    const args = [
      "-p",
      options.prompt,
      "--resume",
      this.sessionId,
      "--output-format",
      "stream-json",
    ];

    return this.run(args, options.cwd, options.timeoutMs);
  }

  /**
   * Respond to a pending tool approval request.
   * Writes "yes" or "no" to the Claude Code process stdin.
   *
   * NOTE (rev. 3): This method is effectively unused in Phase 1.
   * When skipPermissions=true (the default), stdin is set to "ignore"
   * and this method will always throw. Retained for potential Phase 2
   * fallback or removed entirely.
   *
   * @throws {ClaudeRunnerProcessError} If no process is running or not waiting for approval
   */
  respondToApproval(approved: boolean): void {
    if (!this.process?.stdin?.writable) {
      throw new ClaudeRunnerProcessError(
        "Cannot respond to approval: no active process or stdin not writable",
      );
    }

    if (this.status !== "waiting_approval") {
      throw new ClaudeRunnerProcessError(
        `Cannot respond to approval: runner status is "${this.status}", expected "waiting_approval"`,
      );
    }

    const response = approved ? "yes\n" : "no\n";
    this.process.stdin.write(response);
    this.status = "running";
  }

  /**
   * Stop the running Claude Code process.
   * Sends SIGTERM first, then SIGKILL after timeout.
   */
  async stop(): Promise<void> {
    if (this.timeoutHandle) {
      clearTimeout(this.timeoutHandle);
      this.timeoutHandle = null;
    }

    if (!this.process) {
      this.status = "stopped";
      return;
    }

    const proc = this.process;
    this.process = null;
    this.status = "stopped";

    // Try graceful shutdown first
    proc.kill("SIGTERM");

    await new Promise<void>((resolve) => {
      const killTimer = setTimeout(() => {
        proc.kill("SIGKILL");
        resolve();
      }, KILL_TIMEOUT_MS);

      proc.once("exit", () => {
        clearTimeout(killTimer);
        resolve();
      });
    });

    this.readline?.close();
    this.readline = null;
  }

  // --- Private ---

  private async run(
    args: string[],
    cwd: string,
    timeoutMs?: number,
    skipPermissions = true,
  ): Promise<ClaudeRunnerResult> {
    this.accumulatedText = "";
    this.status = "running";

    return new Promise<ClaudeRunnerResult>((resolve, reject) => {
      try {
        // When skipPermissions=true (headless mode), stdin MUST be "ignore".
        // Piping stdin causes Claude Code to hang before emitting any events.
        const stdinMode = skipPermissions ? "ignore" : "pipe";

        this.process = spawn(CLAUDE_BINARY, args, {
          cwd,
          stdio: [stdinMode, "pipe", "pipe"],
          env: { ...process.env },
        });
      } catch (err: unknown) {
        this.status = "error";
        reject(
          new ClaudeRunnerSpawnError(
            `Failed to spawn claude: ${err instanceof Error ? err.message : String(err)}`,
            { cause: err },
          ),
        );
        return;
      }

      // Timeout
      const timeout = timeoutMs ?? DEFAULT_TIMEOUT_MS;
      this.timeoutHandle = setTimeout(() => {
        this.stop().catch(() => {});
        reject(new ClaudeRunnerTimeoutError(`Claude Code timed out after ${timeout}ms`));
      }, timeout);

      // Parse stdout as NDJSON
      this.readline = createInterface({ input: this.process.stdout! });

      this.readline.on("line", (line) => {
        if (!line.trim()) return;

        let event: ClaudeStreamEvent;
        try {
          event = JSON.parse(line) as ClaudeStreamEvent;
        } catch {
          // Non-JSON lines are ignored (Claude Code may emit debug output)
          return;
        }

        this.handleStreamEvent(event);
      });

      // Collect stderr for error reporting
      let stderr = "";
      this.process.stderr?.on("data", (chunk: Buffer) => {
        stderr += chunk.toString();
      });

      // Process exit
      this.process.once("exit", (code, signal) => {
        if (this.timeoutHandle) {
          clearTimeout(this.timeoutHandle);
          this.timeoutHandle = null;
        }

        this.readline?.close();
        this.readline = null;
        this.process = null;

        if (code === 0 || signal === "SIGTERM") {
          this.status = "idle";
          resolve({
            sessionId: this.sessionId ?? "",
            textContent: this.accumulatedText,
            inputTokens: this.lastInputTokens,
            outputTokens: this.lastOutputTokens,
            costUsd: 0,
            durationMs: 0,
          });
        } else {
          this.status = "error";
          reject(
            new ClaudeRunnerProcessError(
              `Claude Code exited with code ${code}${stderr ? `: ${stderr.slice(0, 500)}` : ""}`,
            ),
          );
        }
      });

      // Spawn error (ENOENT, etc.)
      this.process.once("error", (err) => {
        if (this.timeoutHandle) {
          clearTimeout(this.timeoutHandle);
          this.timeoutHandle = null;
        }
        this.status = "error";
        reject(
          new ClaudeRunnerSpawnError(`Failed to spawn claude: ${err.message}`, { cause: err }),
        );
      });
    });
  }

  private handleStreamEvent(event: ClaudeStreamEvent): void {
    switch (event.type) {
      case "system": {
        if (event.subtype === "init" && event.session_id) {
          this.sessionId = event.session_id;
        }
        break;
      }

      case "assistant": {
        const content = event.message?.content;
        if (!content) break;

        for (const block of content) {
          if (block.type === "text" && block.text) {
            this.accumulatedText += block.text;
            this.emit("text", block.text);
          }

          if (block.type === "tool_use" && block.id && block.name) {
            this.status = "waiting_approval";
            this.emit("toolUse", {
              toolUseId: block.id,
              toolName: block.name,
              toolInput: block.input ?? {},
            });
          }
        }
        break;
      }

      case "result": {
        if (event.usage) {
          this.lastInputTokens = event.usage.input_tokens;
          this.lastOutputTokens = event.usage.output_tokens;
        }

        this.emit("result", {
          sessionId: event.session_id ?? this.sessionId ?? "",
          textContent: this.accumulatedText,
          inputTokens: event.usage?.input_tokens ?? 0,
          outputTokens: event.usage?.output_tokens ?? 0,
          costUsd: event.cost_usd ?? 0,
          durationMs: event.duration_ms ?? 0,
        });
        break;
      }

      // tool, error, etc. — ignored for now, handled by Claude Code internally
    }
  }
}
```

```typescript
// src/commands/router.ts
import type { ClaudeRunner } from "../sessions/jorchbot/claude-runner.js";

/** Incoming message from any channel (normalized by OpenClaw) */
interface IncomingMessage {
  text: string;
  senderId: string;
  channel: string;
  messageId: string;
}

/** Result of routing a message */
type RouteResult =
  | { type: "command"; command: string; args: string[] }
  | { type: "prompt"; text: string }
  | { type: "error"; message: string };

interface CommandRouterDeps {
  claudeRunner: ClaudeRunner | null;
  sendReply: (text: string) => Promise<void>;
  sendButtons: (text: string, buttons: Array<{ id: string; title: string }>) => Promise<void>;
  getGatewayStatus: () => GatewayStatus;
}

interface GatewayStatus {
  uptime: number;
  activeSession: { project: string; contextPercent: number } | null;
  channelConnected: boolean;
}

/**
 * Routes incoming messages to the appropriate handler.
 *
 * Rules:
 * 1. `/command` → built-in command handler
 * 2. Free text → forward to ClaudeRunner (active session)
 * 3. No active session + free text → error message
 */
export class CommandRouter {
  private deps: CommandRouterDeps;

  constructor(deps: CommandRouterDeps) {
    this.deps = deps;
  }

  /**
   * Route an incoming message.
   * @throws Never — errors are sent as replies, not thrown
   */
  async route(message: IncomingMessage): Promise<void> {
    const parsed = this.parse(message.text);

    switch (parsed.type) {
      case "command":
        await this.handleCommand(parsed.command, parsed.args);
        break;

      case "prompt":
        await this.handlePrompt(parsed.text);
        break;

      case "error":
        await this.deps.sendReply(parsed.message);
        break;
    }
  }

  private parse(text: string): RouteResult {
    const trimmed = text.trim();

    if (trimmed.startsWith("/")) {
      const parts = trimmed.slice(1).split(/\s+/);
      const command = parts[0]?.toLowerCase() ?? "";
      const args = parts.slice(1);
      return { type: "command", command, args };
    }

    if (!this.deps.claudeRunner) {
      return {
        type: "error",
        message: "No active session. Use /help to see available commands.",
      };
    }

    return { type: "prompt", text: trimmed };
  }

  private async handleCommand(command: string, _args: string[]): Promise<void> {
    switch (command) {
      case "help":
        await this.handleHelp();
        break;

      case "status":
        await this.handleStatus();
        break;

      default:
        await this.deps.sendReply(
          `Unknown command: /${command}\nUse /help to see available commands.`,
        );
    }
  }

  private async handleHelp(): Promise<void> {
    const help = [
      "*Available commands:*",
      "",
      "/help — Show this help",
      "/status — Gateway and active session status",
      "",
      "Send any text to talk to Claude Code.",
    ].join("\n");

    await this.deps.sendReply(help);
  }

  private async handleStatus(): Promise<void> {
    const status = this.deps.getGatewayStatus();

    const lines = [
      "*JorchBot Status*",
      "",
      `Gateway: active (${Math.floor(status.uptime / 60)} min)`,
      `Channel: ${status.channelConnected ? "connected" : "disconnected"}`,
    ];

    if (status.activeSession) {
      lines.push(
        "",
        `*Active session:* ${status.activeSession.project}`,
        `Context: ${status.activeSession.contextPercent}%`,
      );
    } else {
      lines.push("", "No active session.");
    }

    await this.deps.sendReply(lines.join("\n"));
  }

  private async handlePrompt(text: string): Promise<void> {
    const runner = this.deps.claudeRunner;
    if (!runner) {
      await this.deps.sendReply(
        "No active session. Send any message to start a session with Claude Code.",
      );
      return;
    }

    // If runner has a session, resume. Otherwise, start.
    // In Phase 1, there's only ONE session, so we always resume if possible.
    try {
      if (runner.getSessionId()) {
        await runner.resume({ prompt: text, cwd: process.cwd() });
      } else {
        await runner.start({ prompt: text, cwd: process.cwd() });
      }
    } catch (err: unknown) {
      await this.deps.sendReply(
        `Claude Code error: ${err instanceof Error ? err.message : String(err)}`,
      );
    }
  }
}
```

### 3.5 Approval Manager — Detail

> **NOTE (rev. 3)**: In Phase 1, the ApprovalManager operates at the conversational level,
> not per-tool. Since `--dangerously-skip-permissions` is used, Claude executes tools without
> asking. The `PLAN_MODE_PROMPT` system prompt makes Claude present a plan and wait for
> conversational confirmation. The ApprovalManager records these plan-level approvals in the DB.
>
> In Phase 2, this is replaced with real per-tool approval via `PreToolUse` hooks.

The approval manager connects the approval flow between ClaudeRunner and the WhatsApp channel.

```typescript
// src/sessions/jorchbot/approval-manager.ts
import { randomUUID } from "node:crypto";
import type { ClaudeRunner } from "./claude-runner.js";
import { getDb } from "../../db/index.js";
import { approvals } from "../../db/schema.js";
import { eq } from "drizzle-orm";
import type { ApprovalButtonPayload } from "../../../extensions/kapso/src/types.js";

interface ApprovalManagerDeps {
  claudeRunner: ClaudeRunner;
  sessionId: string;
  sendButtons: (text: string, buttons: Array<{ id: string; title: string }>) => Promise<void>;
}

interface PendingApproval {
  id: string;
  toolUseId: string;
  toolName: string;
  toolInput: Record<string, unknown>;
  createdAt: Date;
}

/**
 * Manages the approval flow between ClaudeRunner and WhatsApp buttons.
 *
 * When Claude requests a tool, this manager:
 * 1. Creates a DB record (approvals table)
 * 2. Sends WhatsApp buttons [Yes] [No]
 * 3. On button response, resolves the approval and notifies ClaudeRunner
 */
export class ApprovalManager {
  private pending = new Map<string, PendingApproval>();
  private deps: ApprovalManagerDeps;

  constructor(deps: ApprovalManagerDeps) {
    this.deps = deps;
  }

  /**
   * Handle a tool use request from ClaudeRunner.
   * Creates approval record and sends buttons to WhatsApp.
   */
  async requestApproval(request: {
    toolUseId: string;
    toolName: string;
    toolInput: Record<string, unknown>;
  }): Promise<void> {
    const approvalId = randomUUID();
    const now = new Date();

    // Store in DB
    const db = getDb();
    await db.insert(approvals).values({
      id: approvalId,
      sessionId: this.deps.sessionId,
      action: `${request.toolName}: ${this.summarizeInput(request.toolInput)}`,
      context: JSON.stringify(request.toolInput),
      status: "pending",
      createdAt: now,
    });

    // Track in memory
    this.pending.set(approvalId, {
      id: approvalId,
      toolUseId: request.toolUseId,
      toolName: request.toolName,
      toolInput: request.toolInput,
      createdAt: now,
    });

    // Send buttons to WhatsApp
    const actionSummary = this.summarizeInput(request.toolInput);
    const buttonPayloadApprove: ApprovalButtonPayload = {
      sessionId: this.deps.sessionId,
      approvalId,
      action: "approve",
    };
    const buttonPayloadReject: ApprovalButtonPayload = {
      sessionId: this.deps.sessionId,
      approvalId,
      action: "reject",
    };

    await this.deps.sendButtons(
      `Claude wants to execute:\n> ${request.toolName}: ${actionSummary}`,
      [
        { id: JSON.stringify(buttonPayloadApprove), title: "Yes" },
        { id: JSON.stringify(buttonPayloadReject), title: "No" },
      ],
    );
  }

  /**
   * Handle a button response from WhatsApp.
   * Resolves the pending approval and notifies ClaudeRunner.
   *
   * @returns true if the approval was found and resolved, false otherwise
   */
  async resolveApproval(approvalId: string, approved: boolean): Promise<boolean> {
    const pending = this.pending.get(approvalId);
    if (!pending) return false;

    // Update DB
    const db = getDb();
    await db
      .update(approvals)
      .set({
        status: approved ? "approved" : "rejected",
        resolvedAt: new Date(),
      })
      .where(eq(approvals.id, approvalId));

    // Notify ClaudeRunner
    this.deps.claudeRunner.respondToApproval(approved);

    // Clean up
    this.pending.delete(approvalId);

    return true;
  }

  /**
   * Check if there are pending approvals.
   */
  hasPending(): boolean {
    return this.pending.size > 0;
  }

  private summarizeInput(input: Record<string, unknown>): string {
    // For Bash, show the command
    if (typeof input.command === "string") {
      const cmd = input.command;
      return cmd.length > 100 ? `${cmd.slice(0, 100)}...` : cmd;
    }

    // For Edit/Write, show the file path
    if (typeof input.file_path === "string") {
      return input.file_path;
    }

    // Generic fallback
    return JSON.stringify(input).slice(0, 100);
  }
}
```

```typescript
// src/gateway/jorchbot-start.ts — rewrite for Phase 1

interface StartOptions {

/**

 * 1. Load JorchBot config
 * 2. Initialize database
 * 3. Start OpenClaw gateway server (loads Kapso plugin)
 * 4. Initialize ClaudeRunner (single session)
 * 5. Wire up CommandRouter + ApprovalManager
 * 6. Register shutdown handlers
 *
 * @throws {JorchBotConfigParseError} If config is invalid
 * @throws {JorchBotDbInitError} If database fails to initialize
 * @throws {JorchBotGatewayStartError} If gateway server fails to start
 */
export async function startGateway(opts: StartOptions): Promise<void> {
  try {
    const config = loadConfig();
    const port = opts.port ? Number.parseInt(opts.port, 10) : config.gateway.port;
    const host = opts.host ?? config.gateway.host;

    // Initialize database
    getDb();

    // Initialize ClaudeRunner (single session for Phase 1)
    const claudeRunner = new ClaudeRunner();

    // Start the OpenClaw gateway (loads all plugins including Kapso)
    // The gateway provides the message pipeline, DM pairing, etc.
    // TODO: integrate with startGatewayServer() from OpenClaw
    // This requires wiring the inbound message handler to our CommandRouter

    // Register graceful shutdown
    const shutdown = async () => {
      console.log("[jorchbot] shutting down...");
      await claudeRunner.stop();
      closeDb();
      process.exit(0);
    };
    process.on("SIGINT", () => void shutdown());
    process.on("SIGTERM", () => void shutdown());

    console.log(`[jorchbot] gateway ready on ${host}:${port}`);
    console.log("[jorchbot] database initialized");

    // Hold the process open (gateway server handles requests)
    await new Promise(() => {});
  } catch (err: unknown) {
    if (err instanceof JorchBotError) {
      console.error(`[jorchbot] ${err.name}: ${err.message}`);
      process.exit(1);
    }
    throw err;
  }
}
```

> **NOTE**: The exact integration with `startGatewayServer()` from OpenClaw depends on how the gateway exposes hooks for message handling. This will be resolved during implementation when we have access to the gateway's internal API.

### 3.8 Context Window % Tracking

```typescript
// src/sessions/jorchbot/context-tracker.ts

const MODEL_CONTEXT_LIMITS: Record<string, number> = {
  "claude-opus-4": 200_000,
  "claude-sonnet-4": 200_000,
  "claude-haiku-3.5": 200_000,
  default: 200_000,
};

interface ContextUsage {
  inputTokens: number;
  outputTokens: number;
  totalTokens: number;
  percent: number;
  limit: number;
}

/**
 * Calculate context window usage from Claude Code token metadata.
 */
export function calculateContextUsage(
  inputTokens: number,
  outputTokens: number,
  model = "default",
): ContextUsage {
  const limit = MODEL_CONTEXT_LIMITS[model] ?? MODEL_CONTEXT_LIMITS.default;
  const total = inputTokens + outputTokens;
  const percent = Math.min(100, Math.round((total / limit) * 100));

  return { inputTokens, outputTokens, totalTokens: total, percent, limit };
}

/**
 * Format context usage as a human-readable string.
 * Example: "Context: 23% (47K/200K tokens)"
 */
export function formatContextUsage(usage: ContextUsage): string {
  const totalK = Math.round(usage.totalTokens / 1000);
  const limitK = Math.round(usage.limit / 1000);
  return `Context: ${usage.percent}% (${totalK}K/${limitK}K tokens)`;
}
```

### 3.9 Message Flow — End to End

The complete flow of a message from WhatsApp to Claude Code and back:

```
1. User sends "fix the login bug" on WhatsApp
2. Kapso receives the message and sends it via webhook POST to JorchBot
3. Kapso webhook handler extracts the text and sender phone
4. Access control checks sender (DM pairing, allowlist, or open policy)
5. If unauthorized → send pairing code; if authorized → continue
6. CommandRouter detects it is free text (not a /command)
7. CommandRouter sends the prompt to ClaudeRunner
8. ClaudeRunner executes: claude -p "fix the login bug" --output-format stream-json
     --dangerously-skip-permissions --append-system-prompt <PLAN_MODE_PROMPT>
9. ClaudeRunner parses NDJSON in streaming:
    a. Emits "text" event → JorchBot sends text to WhatsApp
    b. Claude (via PLAN_MODE_PROMPT) presents plan: "I'll need to: ..."
    c. User confirms conversationally ("dale" / "go" / "si")
    d. ClaudeRunner resumes with user's confirmation as new prompt
    e. Claude executes the plan (all tools auto-approved via --dangerously-skip-permissions)
    f. Emits "result" event → JorchBot sends "[session] Completed. Context: 12%"
10. Context % is updated in DB (sessions.contextPercent)
11. Response message is sent via KapsoClient.sendText()
```

> **NOTE**: In Phase 2, step 9b-d is replaced with per-tool approval via `PreToolUse` hooks
> that send WhatsApp buttons [Yes] [No] for each individual tool invocation.

## 4. Design decisions

### 4.1 Why Kapso and not Baileys

| Aspect              | Kapso (official API) | Baileys (reverse-engineered) |
| ------------------- | -------------------- | ---------------------------- |
| Interactive buttons | Yes (up to 3)        | NO (removed since Aug 2024)  |
| Lists               | Yes (up to 10 items) | NO                           |
| Stability           | Official Meta API    | Can break without warning    |
| Rate limits         | Clear and documented | Unknown, frequent bans       |
| Cost                | $0-25/month          | Free                         |
| Auth                | API key              | QR scan + session state      |

**Decision**: Kapso wins due to interactive buttons (critical for approvals) and stability.

### 4.2 Why native fetch() and not the Kapso SDK

Kapso's REST API is simple enough (3-4 endpoints) that a wrapper with fetch() is preferable to the `@kapso/whatsapp-cloud-api` SDK:

- **Fewer dependencies** — smaller attack surface
- **Full control** — error handling exactly as we want
- **Easier to test** — fetch() can be mocked trivially
- **No vendor lock-in** — if Kapso changes, we adapt the wrapper

### 4.3 Why ClaudeRunner uses child_process and not Claude Agent SDK

Claude Agent SDK (TypeScript: `@anthropic-ai/claude-agent-sdk`) would be an alternative, but:

- **ClaudeRunner uses the user's subscription** — no Anthropic API keys
- **Claude Code headless** is the officially supported way for this use case
- **Session persistence** is native (`--resume <session_id>`)
- **CLAUDE.md** is read automatically (no additional config)
- **Tools** (Read, Edit, Bash, etc.) come included

### 4.4 Single session in Phase 1

In Phase 1 there is exactly ONE Claude Code session. This greatly simplifies:

- No Focus Model needed
- No SessionManager needed (direct)
- No routing between sessions
- ClaudeRunner is a singleton per-gateway

Multi-session is implemented in Phase 2.

### 4.5 Dual configuration (JorchBot + OpenClaw)

JorchBot and OpenClaw maintain separate configs:

| Config   | Path                        | Format | Content                                            |
| -------- | --------------------------- | ------ | -------------------------------------------------- |
| JorchBot | `~/.jorchbot/config.json`   | JSON   | gateway port, DB, approvals, channel enabled flags |
| OpenClaw | `~/.jorchbot/jorchbot.json` | JSON5  | channel accounts, DM policies, agent profiles      |

> **NOTE**: The OpenClaw state directory was renamed from `~/.openclaw/` to `~/.jorchbot/`
> (defined in `src/config/paths.ts`: `NEW_STATE_DIRNAME = ".jorchbot"`). The config file
> was also renamed from `openclaw.json` to `jorchbot.json`.

The onboarding (`jorchbot setup`) writes to both files:

1. `~/.jorchbot/config.json` — enables Kapso, saves API key
2. `~/.jorchbot/jorchbot.json` — registers the Kapso account for the Plugin SDK
